# Harness Memory v1 精简规格

日期：2026-11-02。状态：根据本轮批注修订，待审阅；尚未创建 GitHub 仓库、编写产品代码或部署本服务。本文件取代上一版较宽的规格，旧 HTML 介绍不作为本版实施依据。

## 1. 唯一目标

把 XiaoBa / Pi 的日志上传到服务器，按目标选择原始事件组成 Goal Episode，并能根据引用准确读回。关键词搜索只是验证入口。

```text
日志 → 上传并固定保存 → 手动提取 goals → 按 goal 选择事件 ID
                                      ↓
                            Goal Episode：目标 + 事件引用列表
                                      ↓
                         测试搜索 → 按引用读取保存的原文
```

首版不做：自动判断提取时机、压缩钩子、缓存复用、Skill/Wiki、跨窗口目标合并、图扩展、遗忘、正式搜索优化、账号网页、MCP 产品集成或主 agent/branch agent 的生命周期改造。

## 2. 三种对象，引用指向服务器

- 原始记录：上传的一条 JSONL 记录的原始 UTF-8 字节及 hash，存入服务器后不修改。
- 事件：原始记录中的 query/message/tool_call/tool_result，记录原始记录 ID 和字段位置；事件内容从原始记录提取，不由模型重写。
- Goal Episode：目标描述和有序事件 ID 列表；一个事件可以属于多个 episodes。

服务器生成 raw_ref、event_ref、episode_ref。它们都是数据库中不可变对象的标识，不是本地文件路径或会变化的行号。模型重跑生成新 episode，不覆盖旧对象。

读取 event_ref 返回一条事件原文；读取 episode_ref 返回一个 episode 的全部所选事件（按顺序分页），不自动读取其他 episodes 或整场会话；raw_ref 可以下载对应原始记录字节进行核验。客户端日志后来怎样变化，都不改变这些引用的内容。

首版不处理源文件的历史修改同步、版本替换或自动冲突合并。需要上传改写后的文件时，显式作为新 stream 导入；已有服务器原始数据不覆盖。暂不实现删除与遗忘，未知引用返回 404。

保真范围是“上传保存的日志原文”。XiaoBa 普通 turn 日志是一轮汇总，不能补出未记录的中间消息或精确交错顺序，返回中注明 turn_aggregate。Pi 保留 id/parentId，按指定 leaf 的祖先路径处理；有多个候选 leaf 时要求显式指定，不能混串。控制记录保留，但不冒充用户消息或工具结果。不尝试重建每一次真实模型请求。

## 3. 上传只做最基础的闭环

提供一个共用连接器 CLI，加 XiaoBa / Pi 两个格式适配器。适配器输出原始记录和事件字段位置，服务端根据字段位置取得正文，不重复传一份可被改写的“原文正文”。连接器由程序运行，不是 agent 工具。

支持指定一个文件执行上传；加 --watch 时每 30 秒读取新增完整 JSONL 记录。用户需要持续上传时直接让该命令常驻，不改两种 harness 的产品代码，不实现整个日志树自动发现或复杂采集插件。

基础规则仅保留：

1. 配置服务 URL、项目 Key、harness 类型、source_id 和文件/stream_id；标识和已确认偏移保存在本地小状态文件，进度采用原子替换写入。
2. 从确认偏移顺序读取完整记录，小批次发送；每批请求 body 上限 4 MiB，包含传输编码开销。只传完整原生记录；单条就超限时报明确错误并停在该记录，不切片、不跳过、不伪造成功。
3. 服务器事务保存后返回 ACK；客户端收到后推进偏移。服务器按项目、source_id、stream_id、记录字节偏移去重，并检查 hash；重发相同记录返回原来的引用，内容不同报冲突。
4. 请求失败不推进偏移。单次命令报错退出；watch 模式网络失败留到下一次轮询重试，鉴权/内容冲突等配置错误停止并提示。无独立本地持久队列、断点分片协议或复杂退避调度。
5. 末尾半条记录留待下次读取，不提交；文件长度小于确认偏移时报错。源文件提前被删或历史被改，首版不承诺补救，也不做周期性全文件 hash 检查。

不做文件轮转追踪、新旧数据优先级、限速调度、自动补齐所有历史或“服务器已保存数据随本地同步修改”。要补历史就显式上传对应文件。未上传内容的恢复依赖源文件仍存在。

## 4. 先手动触发提取

调用方指定已上传的 stream、记录范围，Pi 另指定 leaf；服务器固定输入事件 ID 列表并创建 extraction run。后续新增日志不进入该次输入。不监听 compaction/checkpoint、不判断 idle/session-end、不设置提取定时器。

每块输入执行两步：

1. 一次模型调用发现 goals，返回目标描述。
2. 每个 goal 一次模型调用选择相关事件 ID。程序校验 ID 属于输入，去重并恢复顺序；工具调用/结果在同一输入内可配对时补齐双方，原本缺失时注明，不编造。

Goal Episode 只保存目标和选中的 ID；读取正文由程序完成。内部选择结果使用简单 JSON 并验证，不依赖专有结构化输出 API，也不额外做模型自评、自动修复或多轮审核流程。结构不合法就显示失败，允许手动重跑。

### 超长输入的最小方案

配置单次输入预算并预留指令/输出空间。未超预算时直接处理，不预先切块。

超预算时按有序事件列表的中间位置二分，尽量选择工具调用/结果组之外的边界；每半独立执行上述两步。仍超预算则继续二分。首版不加重叠窗口、不合并跨块 goals、不引入多层摘要；同一目标跨块可能形成两个 episodes，结果明确带 chunk 标识。这是原文分块，不是只保留半份。

若一条事件或不可分工具组本身超预算，明确失败并保留原始数据，不截断、不进一步切正文。仅对输入过长错误继续二分，普通模型错误直接报告。不承诺分块后与全量输入具有相同的提取质量。

服务端配置一个 OpenAI-compatible chat-completions 模型接口：base_url、api_key、model、输入预算和输出上限；不配置模型也可以上传、读取。模型请求超时默认 120 秒，失败手动重跑。模型密钥不进入客户端日志或公开仓库。

## 5. 一套简单服务

TypeScript、Node.js 20.20+、PostgreSQL 16+。一个服务进程，一个连接器 CLI，两种适配器。原始字节和关系数据都在 PostgreSQL，避免文件与数据库双写。

提取在服务进程内后台执行，同一时间最多一个 run；忙时返回 409。数据库保存运行状态和结果，进程重启后把未完成 run 标为 interrupted，手动重跑；不实现任务队列、独立 worker、租约恢复或复杂断点续算。一个 run 的 episodes 全部成功后一次性发布，失败不混入测试搜索；原始记录始终可读。

## 6. 最小接口

所有数据接口使用项目 Key。来源名只是标签；服务端用 Key 确定项目归属。

| 接口 | 作用 |
|---|---|
| POST /v1/ingest/batches | 保存普通批次，返回 ACK 和原始记录/事件引用 |
| POST /v1/extractions | 指定上传范围，手动开始一次提取，返回 run_id |
| GET /v1/extractions/{id} | 查看 running/completed/failed/interrupted 及结果/错误 |
| POST /v1/episodes/search | 测试关键词检索，返回命中片段及引用 |
| POST /v1/read | 根据 event_ref 或 episode_ref 读取原文 |
| GET /v1/raw/{raw_ref} | 下载指定原始记录字节 |

读取事件列表每页默认 20 条、最大 50 条。单条事件或 raw 下载允许返回完整内容；首版不额外开发正文范围读取，调用方可按 event_ref 控制读取范围。上传大小限制约束单条可保存记录的上限。

测试搜索使用字面子串，不执行 shell，不使用向量和 LLM。keywords[] 支持 AND/OR（默认 AND）；AND 要求同一事件内出现全部词。中文按原文本匹配，ASCII 大小写不敏感。只搜已经发布的 episode 成员事件，按 episode 合并结果；按最新命中事件时间、episode ID 排序，默认 top K=10、最大 50，每条最多 3 个原文片段，每片段最多 400 字符。不做复杂相关性排名、搜索游标或正式检索抽象，之后可以替换。

## 7. 身份和部署保持最低配置

保留项目 ID + 随机项目 Key；管理命令创建项目，服务端保存 Key 的 hash。一个 Key 同时允许该项目上传和读取，所有接口检查归属。没有注册、角色体系、控制台、Key 轮换管理页或设备绑定。

在 Monday 使用独立应用目录、数据库角色和 systemd 服务，不改现有 XiaoBa 版本、不重启已有 bot。优先 SSH 隧道试运行；有现成 HTTPS 才接入公网入口，不为了第一版另开发域名/证书管理。

2026-11-02 已核对根分区 100G、约 56G 可用。发布前再检查资源、现有端口和模型配置。源码公开到 buildsense-ai，建议仓库名 harness-memory，名称冲突时使用 harness-memory-service；原始日志、Key、模型凭证都不入仓库。单服务手动备份数据库即可，首版不搭自动备份/运维控制台。

## 8. 最小验收

- 两种格式各用至少一个合成样本，完成上传 → 手动提取 → 搜索 → episode/event/raw 读取。
- 字段原文与上传内容一致，raw 下载字节 hash 一致；模型不能生成一个不存在的原文引用。
- 相同批次重发不重复保存；失败不推进上传位置；半条日志不被当成完整记录。无需覆盖首版已排除的改写恢复、分片和调度场景。
- 使用可容纳样本及强制二分样本，确认两半均被处理；超大单事件明确失败，原文仍可读；Pi 分支不混串。
- 测试中文、AND/OR、数量上限及项目隔离。
- 实际模型运行后人工检查目标和选择的相关性，报告遗漏和误选；不预设未经验证的 90%/70% 质量指标，不用模拟模型冒充真实模型验收。
