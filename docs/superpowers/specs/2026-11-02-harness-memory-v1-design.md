# Harness Memory v1 设计规格

日期：2026-11-02。状态：书面规格待用户审阅；尚未创建 GitHub 仓库、编写产品代码或部署本服务。

## 1. 目的和验收边界

建立独立于 CatsLog 的会话记忆服务，先接 XiaoBa 和 Pi。首版验证：历史可靠上传后，模型按目标选择相关原始事件，形成 Goal Episode；调用方可以搜索测试，并根据确定性引用准确读取事件或整个 episode。

用户已明确：多 harness 架构；先适配 XiaoBa、Pi；在 Monday 部署；后续在 buildsense-ai 下建立公开仓库；本会话使用 Codex 开发。最近一轮要求优先简单实现，身份系统可以简化。

本规格据此建议：项目 Key 替代注册和网页控制台；服务端调用模型提取，不复用 harness 缓存；首版只生成 Goal Episode，不生成 Skill/Wiki。搜索是验证用实现，可以以后替换。本文包含工程默认值，用户审阅后成为实施基线。

### 首版完成条件

1. XiaoBa、Pi 均有可持续运行的连接器，上传新增日志；停止、断网、重复请求和重启不造成已确认记录丢失或重复落库。
2. 每条存入记录有不可变引用。读取内容与上传保存的原始数据一致，引用不因模型重跑、文件改写或 Key 轮换而指向其他内容。
3. 已上传的固定会话范围可以生成多个目标，每个目标对应有序的原始事件集合。模型只选择事件，不重写这些事件正文。
4. 可以关键词搜索这些 episodes，返回可读取的 episode_ref、event_ref；搜索和原文读取各自可测试。
5. 在 Monday 运行一条真实端到端链路，包含两种 harness 的样本、实际模型提取和原文一致性核验。有明确状态、错误及重新处理入口。

### 首版不做

Skill/Wiki 生成、自动合并历史目标、跨 episode 图生长、随机漫游、遗忘评分、向量检索、正式搜索质量优化、主 agent/branch agent 生命周期改造、完整 MCP 产品集成、注册/登录/网页控制台、团队/计费、模型缓存复用、图片 OCR 和附件全文采集。

后续增加这些能力时，上传协议和原文引用应可沿用；不提前搭建插件市场、微服务或通用图引擎。

## 2. 外部体验

管理员通过服务端命令创建项目，获得 project_id 和一次显示的随机项目 Key。把服务 URL、Key、harness 类型、允许采集的路径配置到对应连接器；连接器生成并持久保存 source_id。之后自动同步，不需要 agent 调用上传工具。

用户或开发者可以通过 CLI/HTTP 查看同步状态、触发一次提取、测试搜索、按引用读取。首版的 agent 工具只需是这些 HTTP 能力的薄封装示例；不修改现有 XiaoBa branch memory，也不把“自动使用记忆改善任务成功率”作为本版验收声明。

流程：

```text
XiaoBa / Pi 持久日志
  → 对应适配器：原生记录 + 可溯源事件 + 安全边界
  → 共用连接器：可靠分批上传
  → 服务端事务：保存、ACK
  → 固定快照任务：发现 goals → 逐 goal 选择事件
  → Goal Episodes
  → 测试搜索返回引用
  → 按引用读取单个事件 / 一个完整 episode / 原生记录
```

## 3. 架构和存储

使用 TypeScript、Node.js 20.20 或更高版本、PostgreSQL 16 或更高版本。一个仓库、一个服务应用、一个连接器应用；两种适配器共用连接器的队列、重试、HTTP 客户端和状态文件。

首版直接将原生 JSONL 记录的字节存为 PostgreSQL bytea，规范化事件与元数据存为 jsonb/关系表。这样原始记录、引用和接收确认在同一个事务内提交，不引入文件存储与数据库双写一致性问题。查询时按需加载原文，不一次性把所有大字段加入搜索结果。

PostgreSQL 同时承载有界提取任务队列。API 和 worker 可使用同一程序的不同启动命令，systemd 分别运行；worker 默认并发 1，防止挤占 Monday 资源。无需 Redis、Kafka、图数据库、向量数据库或容器。

原始日志可能较大，试运行期间记录数据量、上传吞吐、数据库增长及模型成本。存储接口边界保留，但首版不实现第二种存储后端。

## 4. 原始记录、事件与引用

### 4.1 三种持久对象

- NativeRecord：一条上传的原生 JSONL 记录，保留原始 UTF-8 字节、内容 SHA-256、来源文件及版本、记录偏移、harness 和格式版本。额外记录换行信息以支持核对。不能用 JSON 重新序列化的字符串冒充原始字节。
- SourceEvent：从 NativeRecord 定位出来的 query/message/tool_call/tool_result 等事件。保存原生记录引用、JSON Pointer 或内容块位置、可检索正文、调用配对标识、顺序证据和完整性标记。
- GoalEpisode：模型提取的目标描述、固定输入快照引用、有序 event_ref 集合、提取版本和质量标记。标题可以生成，事件正文必须从 SourceEvent/NativeRecord 读取。

ID 是服务端生成的 opaque 标识；客户端不根据 ID 字符串解释来源。引用包含类型和不可变对象 ID，如 evt_<uuid>、ep_<uuid>、raw_<uuid>。ID 不承担授权；所有读取另行检查项目 Key。

客户端在请求内用稳定 local_record_id/local_event_id 表达记录与事件关系；服务端按来源位置、字段路径和 projection_version 唯一映射到引用，并在 ACK 返回映射。模型只接收服务端引用。上传的投影必须能定位到对应原生记录的字段，服务端验证正文一致性；不能接受客户端编造一个与原生记录不一致的“原文事件”。

### 4.2 读取语义

- event_ref：返回一条事件；包含原始字段内容及 raw_ref/来源位置。结构字段可以使用 JSON 包装，但字段正文不由模型重写。
- episode_ref：返回一个固定版本 episode 的目标元数据及所选事件，按可证明的原顺序返回。默认不展开其他 episodes，不返回整场会话。
- raw_ref：返回原生记录的原始字节，支持流式下载或分段读取及整体 SHA-256。事件原文字段与原始 JSON 行是不同视图，两者均可核验。
- 重新提取生成新 episode_ref，保留旧对象及旧引用；搜索默认只展示同一输入范围当前激活的提取版本，防止重试/重跑刷屏。
- 同一事件可以属于多个 episodes；一个 Goal Episode 可以包含不连续的事件。
- 未知引用和非本项目引用均返回 404；删除后返回 410，不重定向到其他内容。

默认每页最多 50 个事件、最多 256 KiB 正文字节；单个巨大事件支持分页的内容范围读取，带 total_bytes、offset、next_cursor 和整体 SHA-256。游标锚定不可变对象及内容，不依赖会移动的文件行号。客户端连续读完后可重构保存的全部正文。

### 4.3 保真边界

服务保证返回上传保存的内容，不保证恢复 harness 从未落盘或已经截断的内容。记录 completeness、ordering_quality 和 projection_version；未知完整性明确标记 unknown，不把未知说成 complete。

XiaoBa turn 日志将 user、assistant.text、tool_calls 汇总在一条记录。可逐字段恢复原文和工具列表，但不保证恢复所有中间 assistant 文本及它们与工具的轮内交错顺序；turn 序号也可能随进程重启重置，不能单独作为幂等键。首版使用该日志作为基础，标记 turn_aggregate/partial_order，不虚构完整事件流。

Pi 按 id/parentId 保存树状历史，不能简单把文件顺序当成同一条对话。按叶子到根的路径形成快照，保留分支身份；不同分支不混成一个 Goal Episode。context_edit/compaction 是带来源的控制记录，不覆盖已保存的原文。原始历史视图与模型可见上下文视图要明确区分，首版提取选择原始路径历史，不声称复原每次 provider 请求。

如后续要求逐条精确还原 XiaoBa 的完整运行上下文，应单独增加事件级采集，而不是在本版悄悄把汇总日志当成完整上下文。

## 5. 上传协议与连接器

### 5.1 采集范围与时机

连接器仅采集用户显式配置的日志根目录，读取完整记录；不扫描整个主目录或自动上传 SSH/模型凭证。配置文件中的项目 Key 不进入上传内容。日志本身可能含敏感信息，试运行使用已授权来源；首版不承诺通用秘密自动识别或清洗。

共用默认策略：有新增完整记录时每 30 秒或累计 256 KiB 触发一批；启动时恢复已持久队列并扫描补传；每 5 分钟进行完整性核对；退出时尽力 flush，可靠性依赖已落盘队列和可重读源文件，不依赖退出回调一定执行。

新数据优先，历史回填交错调度，默认每发送 4 批新数据发送 1 批历史；没有新数据时持续回填。单连接器上传并发 1，历史默认限速 1 MiB/s，均可配置。查看剩余记录/字节数；不得静默跳过旧文件或超大文件。

### 5.2 接收、重试与改写

批次包含 batch_id、source_id、stream_id、generation、adapter_version、完整记录及来源位置。每个批次先在连接器落盘，然后发请求；成功 ACK 后才推进持久水位并删除待传项。服务端在保存完成事务后 ACK。

服务端按 (project_id, batch_id) 幂等，同一 ID、不同内容返回 409。同一来源记录重复进入不同批次也有唯一约束：(project_id, source_id, stream_id, generation, record_position)。其 digest 不同则报冲突，不能静默覆盖。

单次 HTTP body 上限 4 MiB，普通记录尽量凑批。超过限额的单条记录以不可变分片上传，服务端按总长和 SHA-256 校验并原子提交；未完成分片不可检索，不推进对应记录水位。连接器磁盘不足时停止接收新待传项并报错，不伪造成功；源文件在被采集前消失属于可见的采集缺口。

投影引用超大原生记录时只上传字段路径与定位信息，由服务端解析已提交原文，不再将大正文复制进普通批次。服务端可配置单记录存储上限，默认 128 MiB；超出时保留本地待传状态并显示 blocked_record_too_large，提供调整配置或人工跳过的明确操作，绝不自动标记已上传。首版不承诺无限大小的单个 JSON 记录。

文件追加沿用 generation；截断、替换或历史改写创建新 generation。除 size/mtime 外，核对已确认前缀内容哈希，防止同长度改写漏检。首版采用流式前缀哈希校验，不依赖“mtime 没变就一定没变”；周期性核对也检查已经结束的源文件。检测后新版本从头导入；旧引用继续有效，默认搜索隐藏被新版本取代的旧 generation。

对初次回填、重试、源文件改写均不设置“传过一次就永不再传”的标记。网络退避从 1 秒指数增长到 60 秒并加抖动；401/403 停止重试并显示配置错误，413 调整分批或转分片，409 显示来源冲突并停止该流。

连接器状态写入采用临时文件 + 原子替换；source_id 必须跨重启稳定，复制配置安装新实例时生成新 source_id。

## 6. 处理边界和模型提取

### 6.1 输入是什么

服务端对已保存的不可变事件集合建立 snapshot。快照记录 source、stream/generation、分支路径、事件引用和边界原因；任务启动后新上传内容不会改变其输入。

压缩边界优先：适配器观察原生日志里的 compaction/checkpoint 信号，把它转换为统一 boundary 记录。边界只包含已确认落盘的数据；XiaoBa 在 turn 完成后才能记录的信息，等待该完整 turn 上传后再结算，不从普通 runtime 日志推断未保存的工具结果。

缺少可靠压缩信号时，使用 30 分钟没有新记录的 idle 边界；显式停止/用户手动请求也可触发。idle 只是处理触发，不声称任务完成。新数据到来可继续产生后续快照。重复扫描同一边界与输入哈希不重复创建任务。

首版每个快照处理上次已结算边界后的新记录，并额外携带此前最多 32 个完整事件作为上下文重叠（仍受模型预算约束）。每个 episode 都记录其输入范围；本版不承诺自动发现跨多个窗口的同一目标或全历史合并。

### 6.2 模型流程

1. 发现目标：输入带事件 ID、角色、时间、正文的有界历史，输出目标标题、意图及目标锚点事件 ID。允许返回无目标，同时保留原因。
2. 按目标选择：每个 goal 独立输入目标和同一原始历史，输出所选事件 ID/范围及选择理由。模型不能输出“替代原文”的正文。
3. 程序校验：引用必须属于快照；去重、按源顺序排列；所选工具结果若对应调用在快照里，自动补齐调用，反之同理；缺失配对原本不存在时保留并标记，不能补造。
4. 原子保存 episode、成员关系和审计元数据；程序读取原文组装结果。

内部 JSON 是供程序验证的选择协议，不要求用户或 agent 以固定 JSON 思考任务。合法结构不等于相关性正确，因此还必须做人工标注样本评估。

### 6.3 长上下文与失败

配置提取模型的 base_url、api_key、model、context_limit 和 max_output_tokens；首版支持一个 OpenAI-compatible chat-completions 适配器，不承诺所有厂商/格式直接兼容。优先使用 JSON Schema，兼容端不支持时用严格 JSON 校验；不得依赖服务商强制结构输出才能工作。

以包含 system、输出预留和安全余量的 token 预算规划输入。超过预算就按完整事件及工具交换边界分块，每块重叠最多 32 个事件。先各块发现候选目标，再合并标题/锚点并携带来源；按 goal 在这些块中选择并合并 event_ref。所有块都要处理，禁止只留头尾后声称分析了完整历史。

单事件本身超预算时，模型选择视图使用带 event_ref 的分段，分别覆盖全内容；最终选择仍按完整事件单位保存。段落编号只供选择使用，不能成为“已经保存完整原文”的替代品。大数据可能产生很多调用，任务需显示进度、调用量和预算停止原因。

每任务默认最多 64 次模型请求、20 个 goals；达到上限标记 needs_review，已生成产物标记 partial，不把任务标记为完整成功。默认 provider 请求超时 120 秒；可重试错误最多 3 次，结构输出错误允许 1 次修复；失败保留输入和已确认上传记录，可重跑，不影响主 harness 对话。

记录输入快照 hash、模型名称、prompt/schema 版本、阶段、usage、时延、错误与重试次数，不记录模型私密推理过程。不配置模型时允许上传与读取，提取任务明确显示 blocked_configuration。

## 7. 最小 HTTP 接口

所有 /v1 接口使用 Authorization: Bearer <project-key>；project_id 从 Key 决定，不能通过请求覆盖归属。/healthz 不展示项目内容。

| 接口 | 用途与核心输入 | 返回 |
|---|---|---|
| POST /v1/ingest/batches | 幂等批次、来源/版本、原始记录、投影事件、边界 | durable ACK、已接收位置、引用映射 |
| PUT /v1/ingest/records/{upload_id}/parts/{part} | 超大记录的幂等分片，最终提交前校验总长/hash | 分片接收状态 |
| POST /v1/ingest/records/{upload_id}/commit | 声明 manifest 并提交完整超大记录 | 原子记录 ACK 与 raw_ref |
| GET /v1/status | 当前项目的 sources、接收水位、处理水位、待处理量、最近错误 | 有界状态列表，带分页 |
| POST /v1/jobs | 指定已上传 stream/branch、边界/范围，创建提取任务 | job_id、snapshot_ref |
| GET /v1/jobs/{id} | 查看阶段、块进度、结果、失败原因 | pending/running/completed/failed/needs_review/blocked_configuration |
| POST /v1/episodes/search | keywords[]、AND/OR、limit、可选来源/时间筛选 | episode_ref、命中 event_ref、短原文片段、游标 |
| POST /v1/read | event_ref 或 episode_ref、分页游标/内容范围 | 保存的事件正文及来源信息 |
| GET /v1/raw/{raw_ref} | 精确读取原生字节，支持 Range | 原始字节、整体 hash |

任务重跑通过 POST /v1/jobs 提交原 snapshot_ref 和新的 request_id。自动触发任务使用确定性幂等键；显式重跑允许新提取版本但不覆盖旧引用。分片 upload_id 由项目内客户端随机 ID 创建并校验归属，未完成分片 24 小时后清理。

测试搜索是字面子串匹配，不执行 shell grep，不解释正则。keywords 为 1–16 个非空字符串，每个最多 256 个字符；AND 默认，OR 可选；默认 ASCII 大小写不敏感，中文按原文本匹配，不做隐式分词。AND 的所有词须在同一事件正文命中，不能分别从 episode 不同事件拼出假命中。搜索范围为 episode 所选事件正文，首版不搜索未入 episode 的全量原始事件，也不混入生成标题的命中。

结果按命中不同关键词数降序、匹配事件时间降序、固定 ID 排序；一个 episode 只返回一项，附最多 3 个命中事件片段。limit 默认 10、最大 50，片段每条最多 400 个字符。top K 在服务端完成，暂不引入 LLM 排名和图多跳；读取 episode 即展开其完整成员集合，实际传输分页。

## 8. 身份、安全和维护

项目表和 Key 从第一天存在，不建用户表。管理命令支持创建项目、轮换 Key、停用项目、删除指定来源或整个项目。Key 至少 256 位随机熵，服务端只保存哈希；轮换不改变 project_id 和引用。上传、状态、搜索、读取都必须检查项目归属。

同一项目 Key 首版兼具上传/读取权限，未来可添加 scope；Key 只进本地配置，不进提示词、工具响应或公开仓库。TLS 使用已配置域名/证书；没有域名或可信证书时试运行走 SSH 隧道，不通过明文公网传输 Key。上线时检测 Monday 的端口、域名和证书，不能占用已有服务。

首版不自动按年龄删除原文。不再需要的数据通过明确的管理员删除命令处理：暂停相关任务、移除可检索与原始内容、标记引用已删除；文档说明备份保留期，不能假装删除数据库当前行就能立即清除所有备份。
