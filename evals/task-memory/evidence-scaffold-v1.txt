本次实验在正文生成前增加临时原文依据，不改变上面的记忆用途、保留范围和 Markdown 骨架。以下要求替代“只提交 markdown 字段”的传输要求。

先在 support_notes 中列出确实影响本篇记录的少量关键依据，再写 markdown。重点是：用户明确表达或仅假设的要求／选择；影响路线的重要错误与纠正；结果及其实际核验范围。没有这类材料时可为空，不逐条摘录事件，也不把清单当成正文的信息上限。完整经过、必要背景和重要细节仍依据全部候选整理。

每项包含 source_ref（candidate_events 中原有 ref）、quote（该事件 text 中连续、逐字的短原句，不拼接、不加省略号）、record_as（简短说明原话由谁提出、是条件／建议／决定／报告／直接观察中的哪种性质，以及正文据此应该保留什么或避免作何扩大）。按原始事件顺序排列。重要前后变化可分别引用前后原句；未能消解的矛盾保留其条件和来源，不自行裁决。任务描述或助手重复不能替代用户原话作为用户决定的依据。

随后生成完整 markdown。它应忠实保留这些依据的说话人、条件和状态，同时吸收其他必要经过；结尾与正文一致。清单是可检查的原文摘录与记录口径，不是思考过程，不输出写作推理。不要在正文复制此清单或添加 event 级脚注。

使用 submit_memory_document 一次提交完整对象，字段顺序为 support_notes、markdown。support_notes 只用于本轮生成与评估，程序不会将其写入记忆文档；source_refs 仍由程序在文末附上候选 Episode ID。
